## 项目使命

建立一个面向全球用户、以英语为主要语言起步的患者互助讨论社区，专注于分享**颈部／颈椎**和**腰部／腰椎**问题的亲身经历。社区**不提供疾病诊断，也不为具体治疗方法背书**。

## 目标用户

- 正在经历相关症状、希望了解其他患者经历的人
- 愿意分享个人故事和长期康复过程的人
- 家属、照护者及感兴趣的访客（无需证明自己患病）
- 负责落实安全与真实性规则的版主和管理员

## 主要导航（初期设想）

1. 颈部与颈椎
2. 腰部与腰椎
3. 患者经历
4. 康复日记

原稿计划一篇帖子属于一个主要分类，并清楚标注一个发帖意图：

- 我的经历
- 提问／寻求相似经历
- 康复进展
- 家属经历

这些标记代表用户**自述内容**，不属于经过医学验证的信息。

> **现行规则已调整**：第一版不强制选择颈椎或腰椎专区，允许关联多个分类；康复进展复用楼中楼回复，独立康复日记暂缓开发。

## 基础框架完成后计划实现的最小可行产品（MVP）

- 账号注册与登录（原稿计划邮箱验证及凭据安全保护），支持使用公开昵称而非真实姓名
- 文字帖子、评论与主题导航
- 按疾病、症状、持续时间、尝试过的治疗方式以及自述恢复结果进行搜索／筛选（相关资料为选填，并注意隐私）
- 可以持续更新的康复日记
- 内容管理：举报、隐藏、删除、暂停账号、反垃圾信息、请求频率限制
- 个人资料页：细分隐私设置、内容删除／导出、明确的数据保留政策
- 搜索引擎优化（SEO）：可安全公开的帖子页面、语义化元信息，以及正式上线后的 robots／网站地图

> **现行规则已调整**：第一版登录方式为 Google 登录；症状搜索核心为关键词加四项选填筛选（部位、症状标签、持续时间、治疗方式）；康复日记改为楼主在原帖更新进展。详情见 [最新需求总览](requirements/README.md)。

## 初始框架阶段（原稿记录的当时状态）

- 响应式英文首页，并如实显示“即将推出”的状态
- Cloudflare Workers 代码、可选 D1 绑定和初始 SQL 迁移草案
- 简单的只读健康检查、分类和主题 API
- 尚未提供注册、发帖或真实患者数据收集
- 不伪造患者帖子或医疗效果声明

> 注：这是初始阶段描述，不等于截至今天的实时上线状态；**SQL 迁移草案不代表数据库已执行建表**。

## 图片上传

- 将图片上传界面、权限校验和未来私有 R2 集成留到后续开发阶段
- 功能开关默认 **关闭**，不提供公开上传或公开读取接口
- 即使绕过前端界面，Worker 也应返回 HTTP 403
- 不使用公开 R2 域名；启用前检查文件类型、大小、配额、审核机制和访问权限
- 对公众开放之前，先完成仅管理员可用的测试

## 费用与安全控制

- 验证阶段优先使用 Workers 免费套餐和 D1 免费套餐
- 不允许自动升级收费，也不允许用户无限触发高成本查询
- 使用 D1 索引、带有硬性上限的分页，以及适当的缓存
- 根据需要使用 Turnstile、服务端限流、每日额度、WAF 和紧急关闭写入机制
- Cloudflare 的账单提醒**不等于硬性费用上限**
- 未经明确评估与批准，不部署 R2 或其他按量计费的服务

## 可信度、安全与隐私：上线前必须满足的条件

- 明确说明社区用于患者互助，内容不能替代医学建议
- 内容规则禁止危险医疗指示、虚假治愈宣传、诈骗和骚扰
- 处理无意泄露的可识别个人信息，不要求上传医疗记录
- 允许匿名昵称交流、举报以及账号／内容删除
- 上线前规划隐私政策、服务条款、适用司法辖区和年龄要求
- 接受真实用户之前，内容审核流程与安全事件应对流程必须可用

## 技术方案

- GitHub 私有仓库，使用 main 分支
- Cloudflare Workers 与静态资源部署在同一个项目中（不另设 Pages 项目）
- 初期使用 Cloudflare D1 关系数据库，并隔离数据持久化层以便未来迁移
- 仅在图片功能完成审核并获准启用后使用 Cloudflare R2
- 无需外部数据库、VPS 或本地 Java／Tomcat 服务器

## 项目阶段里程碑（原稿计划）

1. **初始框架**：公开首页、安全的只读 API、数据库迁移草案
2. **内部测试**：D1 绑定、测试内容、账号认证、发帖与回复、内容审核
3. **核心社区**：康复记录、筛选与搜索、安全加固
4. **受控上线**：SEO、公开访问、政策文件、备份与监控
5. **可选图片功能**：私有 R2 集成，仅管理员试用，并实施费用保护

原稿当时尚未确定的事项：公开品牌／域名、具体登录提供商、审核人力、隐私与数据保留政策、上线标准和图片配额。

> **更新提示（2026-11-06）**：登录提供商等部分问题已经在新需求中确定；是否仍待讨论应以 [需求决定记录](requirements/decisions.md) 为准，不能将本历史草案的“尚未确定”作为当前状态。
