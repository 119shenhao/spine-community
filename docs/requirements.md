# Spine Community — 第一版需求总汇（2026-11-06）

> **用途：供开发前核对第一版已确定的产品需求。** 本文件汇总此前散落在 `docs/requirements/` 的确认事项，底部保留最初的 v0.1 历史草案。详细规则以 [正式需求主文档](requirements/README.md)、[决定记录](requirements/decisions.md) 及链接的专题文件为准；有冲突时，遵循**日期较新的已确认决定**。下面的“已确认”是需求状态，**不是功能已实现**。

## 当前已确认的功能与规则

### 1. 项目定位、架构
- 面向全球颈椎、腰椎患者交流真实经历的社区，不提供诊断或替代医疗建议；不要求医学证明。
- 一个全球社区、共用账号和数据；两个主要疾病入口为颈椎和腰椎，帖子可关联多个分类，也可以不选分类。正文／回复／标签与界面展示解耦。
- 第一版仅做网页；GitHub 私有仓库、Cloudflare Workers + 静态资源、规划 D1 数据库。数据库迁移**尚未执行**，旧 SQL 是草案。

### 2. 账号、多语言
- 首版仅 Google 登录；游客可以浏览和搜索，发帖、回复、点赞、收藏、关注和举报等操作需登录。使用稳定内部用户 ID，Google 邮箱不作为内容主键。
- 首版七种界面语言：英语、简体中文、西班牙语、巴西葡萄牙语、德语、法语、日语；用户可用任意语言写帖与回复。
- 保存原文与原文语言；自动按读者语言显示按需生成的机器译文并持久缓存，不覆盖原文；随时可查看原文。翻译失败或达到限额时显示原文并告知。需限制费用并保护健康隐私。详见 [多语言需求](requirements/multilingual.md)。

### 3. 发帖、回复、点赞、通知
- 发帖**只有标题和正文必填**；专区、症状、病程、治疗方式等均选填，未分类内容也可浏览与搜索；可关联多个分类／标签。
- 支持回复主帖与评论（楼中楼），每条回复有稳定 ID、所属帖子 ID 和上级回复 ID；作者可编辑、删除自己的评论。删除存在子回复的评论时保留占位，不再公开已删原文或译文。
- 帖子和评论只做点赞、不做点踩；允许给自己的内容点赞；每账号对同一内容最多一个有效赞，再点取消，取消后可以重新点赞。
- 回复帖子、回复评论、点赞帖子／评论均触发相应接收者的**站内通知**；自己对自己的操作不通知自己。右上角铃铛、未读角标、通知列表、点击跳转并标已读、全部已读，多个点赞可合并展示。首版不发邮件或移动推送。

### 4. 全球症状搜索与相似结果
- 关键词搜索加四组**可选**筛选：身体部位、症状标签、持续时间、治疗方式；不要求帖子事先填过所有字段。
- 默认搜索**所有语言**的公开帖子。利用多语言症状同义词／概念 ID、关键词扩展及原文全文索引，不能依赖已有译文缓存才能搜索到外文内容。
- 默认排序“最相关”，可切换“最新”和“讨论最多”；症状型查询至少匹配一项部位或症状，匹配项越多通常越靠前，普通非症状检索不强制有症状。明确设置的筛选条件对正常结果严格生效。
- 每条显示标题、标签、自动摘要、时间、作者自愿公开的地区、原文语言；标题和摘要高亮命中表达及翻译后对应词。每批 20 条、下滑加载更多。
- 没有完全匹配时**自动展示独立标注的相似结果**，说明匹配与未匹配条件；放宽筛选不私下更改原查询；另有调整条件／发布求助帖入口。相似并不意味着同病。详见 [搜索需求](requirements/search-progress-2026-11-06.md)。

### 5. 楼主进展、关注与收藏
- 首版**不做独立康复日记模块**。只有楼主可用“更新进展”在原帖发布特殊类型回复，标明日期与第几次更新。
- 帖子顶部“楼主进展”默认显示最近一两次，支持查看完整时间线；同一条记录也出现在普通回复列表，顶部可跳转定位。**双入口、单份数据**。登录用户可回复进展、楼中楼讨论和点赞。
- **关注帖子**与关注楼主本人不同。用户主动关注某帖后，楼主更新进展时向关注者发送站内通知；阅读、评论或收藏均不自动关注，首版不做关注个人。
- **收藏帖子**：登录后可收藏；个人中心“我的收藏”显示收藏列表，点击回到原帖；不做收藏分类和标签。收藏与关注彼此独立，不自动触发进展通知。详见 [进展与关注](requirements/author-progress-2026-11-06.md)、[决定记录](requirements/decisions.md)。

### 6. 个人中心、隐私与删除
- 第一版个人中心只需要“我的帖子”“我的回复”“我的收藏”“关注的帖子／进展提醒”等基础入口，不做复杂社交主页。
- 可以使用匿名昵称，不强制真实姓名；帖子默认公开，发布前提醒不要泄露身份、联系方式和敏感医疗资料。站长有最高业务管理权，但 Google 令牌、密钥等机密不应在后台明文展示；版主仅可看履职必需信息。
- **删掉已有回复的主帖时保留“该帖子已删除”占位**，其他人的回复继续保留；删除主帖的公开正文、译文和索引缓存应同步失效。用户可申请账号注销和数据删除，具体合规处理与保留期限上线前明确。详见 [个人中心与隐私删除](requirements/profile-privacy-deletion-2026-11-06.md)。

### 7. 内容安全、后台权限、日志与统计
- 普通帖子／评论先发布后审核；规则识别广告、可疑链接、重复及高频内容。低风险直接发布，中风险作者可见而公开待审，高风险拦截并允许复核。首版不依赖付费 AI。
- 登录用户可举报帖子及评论，每用户对同一内容最多一条有效举报。举报人数再多也**不只凭人数自动隐藏**，管理员结合风险优先处理；提供复核和必要的操作记录。
- 后台设计**站长／版主**两级，初期可只启用站长。版主可审核、隐藏／恢复、临时禁言 **1／3／7／30 天**；永久封禁、永久删除、系统设置、分类管理及任命版主由站长负责。管理员不擅自改写患者原文。
- 日志记录操作人、时间、对象、动作与原因。每天统计注册、帖子、评论、举报数；流量指标为 UV、PV、按滚动五分钟活跃访客估算的每日最高同时活跃人数、每小时 PV 峰值及发生时段。提供 7／30 天趋势；**第一版不按国家统计**。详见 [后台审核与统计](requirements/admin-moderation-analytics-2026-11-06.md)。

### 8. 第一版上线与执行边界
- 开发顺序建议：身份与帖子基础 → 多语言与搜索互动 → 审核管理 → 隐私安全测试与受控上线。
- 公开前必须有账号安全、垃圾内容治理、举报处理、隐私政策和用户删除流程；SEO 及图片上传仅在满足相应安全条件后开放，图片／R2 首版默认关闭。
- 保护 Cloudflare 免费额度；不得在无授权情况下启用收费服务。**当前仅确认需求、未授权修改代码或执行数据库迁移**。只改 `docs/` 不触发此前已经确认的文档专用部署过滤规则（依赖控制台设置）。
- 尚待实现时细化：搜索权重、评论折叠、编辑历史、账号注销保留期、审核阈值、统计去重与时区、第三方翻译合规、SEO 和上线条件。

# Spine Community — 产品需求初版草案（v0.1，历史存档·中文版）

> **注意：这是项目初期英文草案的中文翻译，保留原有的构想和阶段记录，不代表当前已确认需求。**
>
> **当前有效的需求以 [需求总览（主文档）](requirements/README.md) 和 [需求决定记录](requirements/decisions.md) 为准。** 2026-11-06 已经调整的重点包括：首版只提供 Google 登录；帖子可不选分类且支持多分类关联；首版不做独立康复日记；全球多语言共库；数据库迁移尚未执行。
>
> 这份文件可作为项目早期规划的历史参考。以下为原稿内容翻译；其中部分“计划”和“待定事项”已过时。

## 项目使命

建立一个面向全球用户、以英语为主要语言起步的患者互助讨论社区，专注于分享**颈部／颈椎**和**腰部／腰椎**问题的亲身经历。社区**不提供疾病诊断，也不为具体治疗方法背书**。

## 目标用户

- 正在经历相关症状、希望了解其他患者经历的人
- 愿意分享个人故事和长期康复过程的人
- 家属、照护者及感兴趣的访客（无需证明自己患病）
- 负责落实安全与真实性规则的版主和管理员

## 主要导航（初期设想）

1. 颈部与颈椎
2. 腰部与腰椎
3. 患者经历
4. 康复日记

原稿计划一篇帖子属于一个主要分类，并清楚标注一个发帖意图：

- 我的经历
- 提问／寻求相似经历
- 康复进展
- 家属经历

这些标记代表用户**自述内容**，不属于经过医学验证的信息。

> **现行规则已调整**：第一版不强制选择颈椎或腰椎专区，允许关联多个分类；康复进展复用楼中楼回复，独立康复日记暂缓开发。

## 基础框架完成后计划实现的最小可行产品（MVP）

- 账号注册与登录（原稿计划邮箱验证及凭据安全保护），支持使用公开昵称而非真实姓名
- 文字帖子、评论与主题导航
- 按疾病、症状、持续时间、尝试过的治疗方式以及自述恢复结果进行搜索／筛选（相关资料为选填，并注意隐私）
- 可以持续更新的康复日记
- 内容管理：举报、隐藏、删除、暂停账号、反垃圾信息、请求频率限制
- 个人资料页：细分隐私设置、内容删除／导出、明确的数据保留政策
- 搜索引擎优化（SEO）：可安全公开的帖子页面、语义化元信息，以及正式上线后的 robots／网站地图

> **现行规则已调整**：第一版登录方式为 Google 登录；症状搜索核心为关键词加四项选填筛选（部位、症状标签、持续时间、治疗方式）；康复日记改为楼主在原帖更新进展。详情见 [最新需求总览](requirements/README.md)。

## 初始框架阶段（原稿记录的当时状态）

- 响应式英文首页，并如实显示“即将推出”的状态
- Cloudflare Workers 代码、可选 D1 绑定和初始 SQL 迁移草案
- 简单的只读健康检查、分类和主题 API
- 尚未提供注册、发帖或真实患者数据收集
- 不伪造患者帖子或医疗效果声明

> 注：这是初始阶段描述，不等于截至今天的实时上线状态；**SQL 迁移草案不代表数据库已执行建表**。

## 图片上传

- 将图片上传界面、权限校验和未来私有 R2 集成留到后续开发阶段
- 功能开关默认 **关闭**，不提供公开上传或公开读取接口
- 即使绕过前端界面，Worker 也应返回 HTTP 403
- 不使用公开 R2 域名；启用前检查文件类型、大小、配额、审核机制和访问权限
- 对公众开放之前，先完成仅管理员可用的测试

## 费用与安全控制

- 验证阶段优先使用 Workers 免费套餐和 D1 免费套餐
- 不允许自动升级收费，也不允许用户无限触发高成本查询
- 使用 D1 索引、带有硬性上限的分页，以及适当的缓存
- 根据需要使用 Turnstile、服务端限流、每日额度、WAF 和紧急关闭写入机制
- Cloudflare 的账单提醒**不等于硬性费用上限**
- 未经明确评估与批准，不部署 R2 或其他按量计费的服务

## 可信度、安全与隐私：上线前必须满足的条件

- 明确说明社区用于患者互助，内容不能替代医学建议
- 内容规则禁止危险医疗指示、虚假治愈宣传、诈骗和骚扰
- 处理无意泄露的可识别个人信息，不要求上传医疗记录
- 允许匿名昵称交流、举报以及账号／内容删除
- 上线前规划隐私政策、服务条款、适用司法辖区和年龄要求
- 接受真实用户之前，内容审核流程与安全事件应对流程必须可用

## 技术方案

- GitHub 私有仓库，使用 main 分支
- Cloudflare Workers 与静态资源部署在同一个项目中（不另设 Pages 项目）
- 初期使用 Cloudflare D1 关系数据库，并隔离数据持久化层以便未来迁移
- 仅在图片功能完成审核并获准启用后使用 Cloudflare R2
- 无需外部数据库、VPS 或本地 Java／Tomcat 服务器

## 项目阶段里程碑（原稿计划）

1. **初始框架**：公开首页、安全的只读 API、数据库迁移草案
2. **内部测试**：D1 绑定、测试内容、账号认证、发帖与回复、内容审核
3. **核心社区**：康复记录、筛选与搜索、安全加固
4. **受控上线**：SEO、公开访问、政策文件、备份与监控
5. **可选图片功能**：私有 R2 集成，仅管理员试用，并实施费用保护

原稿当时尚未确定的事项：公开品牌／域名、具体登录提供商、审核人力、隐私与数据保留政策、上线标准和图片配额。

> **更新提示（2026-11-06）**：登录提供商等部分问题已经在新需求中确定；是否仍待讨论应以 [需求决定记录](requirements/decisions.md) 为准，不能将本历史草案的“尚未确定”作为当前状态。
