# 帖子与跟帖导入接口

日期：2026-11-06。状态：**导入能力已确认；接口细节为设计建议，尚未实现。**

## 已确认的新增需求

- 支持通过 API 导入帖子，以及向帖子导入跟帖／回复，方便外部程序提交已经整理好的数据。
- 回复必须关联正确的帖子；楼中楼回复沿用现有稳定的父子关系，不因导入而丢失讨论结构。
- 本条是新增产品需求，不代表已有导入接口，也不代表已经导入任何外站内容。

## 建议的接口划分（待细化）

| 能力 | 用途 |
| --- | --- |
| 导入帖子 | 提交标题、正文等内容，返回本站帖子 ID |
| 导入跟帖 | 指定所属帖子，可指定上级回复，返回本站回复 ID |
| 批量导入 | 同次提交帖子及其回复，返回逐条处理结果及外部 ID 到本站 ID 的对应关系 |

接口路径、单条与批量是否同时提供、批次上限、请求格式及错误码，在开发前确定。此表不是已实现的 API 契约。

## 建议的数据与处理规则（待细化）

- 帖子保存标题、原文正文、原文语言；分类／症状标签仍为可选。
- 支持来源站点、外部帖子／回复 ID、原始发布时间和原始链接；原始时间与实际导入时间分开保存。
- 用来源站点与外部 ID 或明确的幂等键去重；重试不重复创建。重复内容是跳过、报冲突还是允许更新，另行确定，不能默默覆盖已编辑内容。
- 先建立帖子／父回复，再导入子回复；跨帖引用、父项缺失或循环引用明确报错。
- 导入结果返回成功、重复、失败等逐条状态，方便补传；事务范围及失败重试方式在实现时确定。
- 导入接口使用独立且可撤销的授权，仅允许获授权的管理者或导入程序调用；不能因绕过浏览器而绕过正文校验、审核和安全限制。
- 历史导入是否触发通知、影响最新排序和统计，需明确规则；建议避免历史导入批量触发用户通知。

## 此前讨论的内容组织方向（实施前核对）

此前讨论过：外站内容统一归于“未知用户”，保存来源链接但暂不在前台显示，前台展示标题、正文和跟帖。具体作者映射和导入标识应在实施前核对；尤其不能仅因统一为同一内部用户，就将所有跟帖视为楼主发言或授予普通用户编辑全部导入内容的权限。
