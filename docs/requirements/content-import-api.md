# 帖子与跟帖导入接口

日期：2026-11-06。状态：**导入能力已确认；环境与免密规则已确认，统一账号及批量导入方向已确认，其余接口细节为设计建议，代码已实现并通过本地测试；远程验收见下文。**

## 已确认的新增需求

- 支持通过 API 导入帖子，以及向帖子导入跟帖／回复，方便外部程序提交已经整理好的数据。
- 回复必须关联正确的帖子；楼中楼回复沿用现有稳定的父子关系，不因导入而丢失讨论结构。
- 支持用户批量生成内容后通过接口导入，不限定内容来自其他网站。
- 所有导入帖子和跟帖统一关联数据库中的一个“未知用户”系统账号，前端作者名也统一显示为“未知用户”，不挂站长账号。
- 不再设计原站作者映射或原站帖子／回复标识，不要求来源站点、原始链接等来源信息。此次决定替代先前保留来源及区分外部作者的设计建议。
- “未知用户”为内容归属账号，不提供登录能力；接口不允许调用者选择其他用户来冒名发帖。
- 用户已授权实现接口、创建账号并测试；实现与实际远程状态以本文末尾的执行记录为准。

## 环境与访问规则（已确认，2026-11-06）

- **仅开发／预览环境允许导入；生产环境导入接口暂时关闭。**
- **开发导入接口暂不使用密钥，不要求登录；知道接口地址即可提交帖子和跟帖。** 这是开发导入专用规则，不改变普通发帖、管理后台等既有鉴权规则。
- 开发预览网址可被公网访问，因此任何知道或发现开发导入地址的人都可能向测试库提交数据；接口地址不作为身份凭证或安全保障。
- 生产环境必须在服务端拒绝所有导入请求，在写库前终止；知道路径、带登录态或传入任意参数均不能开启。不能只隐藏按钮。
- 环境判断与允许开关由部署端控制；未明确识别为允许的开发环境时默认关闭，不能通过请求参数伪装成开发环境。
- 开发导入只写隔离测试 D1，不连接生产库；测试数据不会随代码合并同步到生产。
- 本次免密简化只针对开发环境；将来开放生产导入需用户另行明确决定，不能自动沿用免密规则。
- 免密不代表取消正文格式、长度、回复归属等数据校验。批次上限、限流及去重的具体方案仍待细化。

## 接口划分（已实现）

| 能力 | 用途 |
| --- | --- |
| 导入帖子 | 提交标题、正文等内容，返回本站帖子 ID |
| 导入跟帖 | 指定所属帖子，可指定上级回复，返回本站回复 ID |
| 批量导入 | 同次提交帖子及其回复，返回逐条处理结果及本站帖子／回复 ID |

单条与批量接口均已实现。具体路径、请求格式、限额和错误码以[接口用法](../import-api.md)为准。

## 数据与处理规则

- 帖子保存标题、原文正文、原文语言；分类／症状标签仍为可选。
- 只需输入内容及其本站归属关系；不依赖任何原站字段。当前使用服务端创建时间，不接受客户端指定时间。
- 采用整个请求的规范化 JSON 哈希去重，无需原站 ID 或调用方提供幂等键；重试返回已有内容 ID，不覆盖已有内容。不同批次的部分相同内容不逐条去重。
- 先建立帖子／父回复，再导入子回复；跨帖引用、父项缺失或循环引用明确报错。
- 导入成功返回每条内容 ID 和审核状态；同一请求重试标记为已重放。整批先校验、再原子写入，一条失败则整批不创建内容。
- 按上述已确认规则：开发导入接口暂不要求密钥或登录，生产关闭；校验正文与关联数据，沿用已有风险审核，并限制单批大小和提交频率。
- 导入不发送通知；按服务端当前时间参与最新排序，统计计入导入当日的帖子／评论数，不计为用户注册或页面访问。

## 统一账号下的帖子／回复关系

所有导入内容都属于同一个“未知用户”，不再区分所谓的原站楼主和其他发言人。但本站仍需有正常的帖子 ID、回复 ID、所属帖子和上级回复关系，才能把跟帖显示在正确的位置；这些不是原站标识。

批量提交采用“一个帖子附带其回复”的结构，也支持为已有帖子提交回复。导入普通跟帖不应仅因作者账号与帖子相同就自动转成“更新进展”，也不能因此授予调用者修改已有内容或管理后台的权限。
