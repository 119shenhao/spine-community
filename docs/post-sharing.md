# Post sharing / 帖子分享

## 用户需求（2026-11-13）

在每篇**公开已发布**帖子的详情页**底部（正文、交互操作与进展更新之后，评论区之前）**显示“分享”按钮。点击时提供 Facebook、X、Reddit、LinkedIn、WhatsApp、Telegram、Bluesky，以及国内的微信、QQ、抖音、B站、微博、QQ空间分享入口，手机浏览器支持 Web Share API 时提供系统分享，另外始终有复制帖子链接功能。未登录访客也可分享。被删除、隐藏、未发布的内容不展示公开分享入口。

## 实现规则

- 分享网址采用当前站点源地址和 /topic/{id} 独立 History API 路由；不携带临时评论定位、查询参数或追踪参数。开发预览分享开发链接，生产分享生产链接，避免将未发布的开发帖误指向生产。
- 分享标题使用帖子的原始标题，社交网站通过对应主题页已有的 Open Graph 元信息预览内容。
- 所有分享必须由访客明确点击触发，站点不主动加载第三方 SDK、嵌入件或跟踪脚本；使用普通安全外链（noopener/noreferrer）。对于没有通用网页分享端点的社交 App，可以使用系统分享或复制链接粘贴。
- 打开菜单、复制链接不刷新或重新获取帖子，不增加 Worker 或 D1 请求；不需要新数据表、数据库迁移或后端 API。
- 界面提供英文、简体中文、繁体中文、西班牙语、巴西葡萄牙语、德语、法语、日语翻译。
- iPhone/Android、电脑端均应可正常操作。Web Share API 取消分享不报错；复制链接失败显示提示并保留可手动选中的链接。
- 点击帖子底部「分享」按钮时，**如果浏览器支持 Web Share API，必须直接、同步地在该用户点击事件内调用系统分享面板**，不要先 `await` 其他异步调用，也不要先弹自定义对话框，以免 iOS Safari 丢失 transient user activation。
- 手机系统分享成功后不显示额外弹窗；用户取消系统分享、系统分享报错或者不支持 Web Share API 时才打开论坛自定义备用分享弹窗，取消不显示错误 toast。备用弹窗仍允许再次发起系统分享。
- 备用弹窗中的 Facebook、X、Reddit、LinkedIn、WhatsApp、Telegram、Bluesky **只显示各平台本地内联 SVG 品牌图标，不显示挤在一起的文字名称**；但每个图标必须有 `aria-label`/辅助技术可读名称和鼠标 title。四列响应式图标网格，移动端不能超出弹窗。
- 翻译字段和 CSS/JS 必须在同一版前端构建中部署，严禁出现 `sharePost`、`copyLink`、`shareSystem` 等未翻译的键名，也不应丢失分享弹窗 CSS。继续依赖构建脚本创建同一 revision 下的全部前端资源，版本一致性由已有 `scripts/verify-versioned-frontend.mjs` 验证。

- 开发优先在 `feature/v1-community-build-20261106` 完成，生产发布须另外执行既定“发布新版本”任务，不由本次功能开发自动发布。

## 中国平台支持方式（2026-11-13）

- **QQ**：用户点击图标，打开 QQ 网页分享入口（`https://connect.qq.com/widget/shareqq/index.html`，传帖子 URL、标题）。
- **微博**：使用微博网页分享入口（`https://service.weibo.com/share/share.php`），传帖子 URL、标题。
- **QQ空间**：使用其网页分享入口（`https://sns.qzone.qq.com/cgi-bin/qzshare/cgi_qzshare_onekey`），传 URL、标题。
- **微信、抖音、B站**：目前没有经验证通用于第三方 H5 文本帖子链接的直接分享端点，**绝不伪造 `weixin://share`、`douyin://share` 或 B站链接**。页面优先提供浏览器系统分享菜单（能否出现在应用列表取决于操作系统/安装情况/应用能力）；备用图标点击可复制帖子链接，显示「链接已复制，请打开 XX 粘贴分享」。这些入口不是“已直接分享到对应 App”的承诺。
- 备用弹窗不分国内/国际平台，也不显示分组标题；统一按原有国际平台在上、国内平台紧接在下的固定顺序排列；每个平台使用本地 SVG 图标，按钮和链接保留可读的 `aria-label`。仅用户实际点击时复制或打开站外分享页面，不加载第三方 SDK，不记录/伪造分享成功次数。
- 不改变发帖、数据同步和翻译链路；生产环境是否允许被各平台内置浏览器打开，还要遵循各平台的外链规则与实际检验。

## 验收

1. 公开帖子详情页底部、评论区之前存在分享按钮，未登录也可用；未公开帖子不可分享。
2. 各平台链接 URL 参数正确且包含帖子独立地址和标题（视平台接受参数而定）。
3. 点击复制链接并从链接打开帖子能直达详情；移动端系统分享可用时显示额外选项，系统取消不报错。
4. 无完整页面刷新、无无关 API 请求；按钮和弹窗在窄屏、全部支持语言下可用。
5. iPhone/Android 的一次点击直接弹出原生系统分享菜单；取消时图标备用弹窗可用；不支持 Web Share 时直接展示图标备用弹窗。
6. 分享备用弹窗的每种平台有独立 SVG 图标和无障碍名称；任何语言都不显示原始 i18n 字段键；JS/CSS/词条与本次构建版本一致。
7. 微信、抖音、B站图标点击复制链接并反馈，QQ、微博、QQ空间带 URL/标题打开网页分享入口；所有 13 个平台图标无障碍名称可识别，窄屏不溢出。
