# Spine Community — 第一版需求总汇（2026-11-06）

> **用途：供开发前核对第一版已确定的产品需求。** 本文件汇总此前散落在 `docs/requirements/` 的确认事项，底部保留最初的 v0.1 历史草案。详细规则以 [正式需求主文档](../开发需求/项目需求总览.md)、[决定记录](../开发需求/需求决策记录.md) 及链接的专题文件为准；有冲突时，遵循**日期较新的已确认决定**。下面的“已确认”是需求状态，**不是功能已实现**。

## 当前已确认的功能与规则

### 1. 项目定位、架构
- 面向全球颈椎、腰椎患者交流真实经历的社区，不提供诊断或替代医疗建议；不要求医学证明。
- 一个全球社区、共用账号和数据；两个主要疾病入口为颈椎和腰椎，帖子可关联多个分类，也可以不选分类。正文／回复／标签与界面展示解耦。
- 第一版仅做网页；GitHub 私有仓库、Cloudflare Workers + 静态资源、规划 D1 数据库。数据库迁移**尚未执行**，旧 SQL 是草案。

### 2. 账号、多语言
- 首版仅 Google 登录；游客可以浏览和搜索，发帖、回复、点赞、收藏、关注和举报等操作需登录。使用稳定内部用户 ID，Google 邮箱不作为内容主键。
- 首版七种界面语言：英语、简体中文、西班牙语、巴西葡萄牙语、德语、法语、日语；用户可用任意语言写帖与回复。
- 保存原文与原文语言；自动按读者语言显示按需生成的机器译文并持久缓存，不覆盖原文；随时可查看原文。翻译失败或达到限额时显示原文并告知。需限制费用并保护健康隐私。详见 [多语言需求](../开发需求/多语言与自动翻译需求.md)。

### 3. 发帖、回复、点赞、通知
- 发帖**只有标题和正文必填**；专区、症状、病程、治疗方式等均选填，未分类内容也可浏览与搜索；可关联多个分类／标签。
- 支持回复主帖与评论（楼中楼），每条回复有稳定 ID、所属帖子 ID 和上级回复 ID；作者可编辑、删除自己的评论。删除存在子回复的评论时保留占位，不再公开已删原文或译文。
- 帖子和评论只做点赞、不做点踩；允许给自己的内容点赞；每账号对同一内容最多一个有效赞，再点取消，取消后可以重新点赞。
- 回复帖子、回复评论、点赞帖子／评论均触发相应接收者的**站内通知**；自己对自己的操作不通知自己。右上角铃铛、未读角标、通知列表、点击跳转并标已读、全部已读，多个点赞可合并展示。首版不发邮件或移动推送。

### 4. 全球症状搜索与相似结果
- 关键词搜索加四组**可选**筛选：身体部位、症状标签、持续时间、治疗方式；不要求帖子事先填过所有字段。
- 默认搜索**所有语言**的公开帖子。利用多语言症状同义词／概念 ID、关键词扩展及原文全文索引，不能依赖已有译文缓存才能搜索到外文内容。
- 默认排序“最相关”，可切换“最新”和“讨论最多”；症状型查询至少匹配一项部位或症状，匹配项越多通常越靠前，普通非症状检索不强制有症状。明确设置的筛选条件对正常结果严格生效。
- 每条显示标题、标签、自动摘要、时间、作者自愿公开的地区、原文语言；标题和摘要高亮命中表达及翻译后对应词。每批 20 条、下滑加载更多。
- 没有完全匹配时**自动展示独立标注的相似结果**，说明匹配与未匹配条件；放宽筛选不私下更改原查询；另有调整条件／发布求助帖入口。相似并不意味着同病。详见 [搜索需求](../开发需求/跨语言症状搜索需求.md)。

### 5. 楼主进展、关注与收藏
- 首版**不做独立康复日记模块**。只有楼主可用“更新进展”在原帖发布特殊类型回复，标明日期与第几次更新。
- 帖子顶部“楼主进展”默认显示最近一两次，支持查看完整时间线；同一条记录也出现在普通回复列表，顶部可跳转定位。**双入口、单份数据**。登录用户可回复进展、楼中楼讨论和点赞。
- **关注帖子**与关注楼主本人不同。用户主动关注某帖后，楼主更新进展时向关注者发送站内通知；阅读、评论或收藏均不自动关注，首版不做关注个人。
- **收藏帖子**：登录后可收藏；个人中心“我的收藏”显示收藏列表，点击回到原帖；不做收藏分类和标签。收藏与关注彼此独立，不自动触发进展通知。详见 [进展与关注](../开发需求/楼主进展与帖子关注需求.md)、[决定记录](../开发需求/需求决策记录.md)。

### 6. 个人中心、隐私与删除
- 第一版个人中心只需要“我的帖子”“我的回复”“我的收藏”“关注的帖子／进展提醒”等基础入口，不做复杂社交主页。
- 可以使用匿名昵称，不强制真实姓名；帖子默认公开，发布前提醒不要泄露身份、联系方式和敏感医疗资料。站长有最高业务管理权，但 Google 令牌、密钥等机密不应在后台明文展示；版主仅可看履职必需信息。
- **删掉已有回复的主帖时保留“该帖子已删除”占位**，其他人的回复继续保留；删除主帖的公开正文、译文和索引缓存应同步失效。用户可申请账号注销和数据删除，具体合规处理与保留期限上线前明确。详见 [个人中心与隐私删除](../开发需求/个人中心隐私与删帖需求.md)。

### 7. 内容安全、后台权限、日志与统计
- 普通帖子／评论先发布后审核；规则识别广告、可疑链接、重复及高频内容。低风险直接发布，中风险作者可见而公开待审，高风险拦截并允许复核。首版不依赖付费 AI。
- 登录用户可举报帖子及评论，每用户对同一内容最多一条有效举报。举报人数再多也**不只凭人数自动隐藏**，管理员结合风险优先处理；提供复核和必要的操作记录。
- 后台设计**站长／版主**两级，初期可只启用站长。版主可审核、隐藏／恢复、临时禁言 **1／3／7／30 天**；永久封禁、永久删除、系统设置、分类管理及任命版主由站长负责。管理员不擅自改写患者原文。
- 日志记录操作人、时间、对象、动作与原因。每天统计注册、帖子、评论、举报数；流量指标为 UV、PV、按滚动五分钟活跃访客估算的每日最高同时活跃人数、每小时 PV 峰值及发生时段。提供 7／30 天趋势；**第一版不按国家统计**。详见 [后台审核与统计](../开发需求/后台管理审核与统计需求.md)。

### 8. 第一版上线与执行边界
- 开发顺序建议：身份与帖子基础 → 多语言与搜索互动 → 审核管理 → 隐私安全测试与受控上线。
- 公开前必须有账号安全、垃圾内容治理、举报处理、隐私政策和用户删除流程；SEO 及图片上传仅在满足相应安全条件后开放，图片／R2 首版默认关闭。
- 保护 Cloudflare 免费额度；不得在无授权情况下启用收费服务。**当前仅确认需求、未授权修改代码或执行数据库迁移**。只改 `docs/` 不触发此前已经确认的文档专用部署过滤规则（依赖控制台设置）。
- 尚待实现时细化：搜索权重、评论折叠、编辑历史、账号注销保留期、审核阈值、统计去重与时区、第三方翻译合规、SEO 和上线条件。
