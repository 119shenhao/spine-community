## 已落实的开发规则

1. 无可靠原文语言证据时保留 `und`，不得默认 `en`；`source_lang_mode='legacy'` 表示尚未确认，不得生成伪造的验证证明。
2. 有效的作者或管理员人工指定优先；历史自动修正不得覆盖有效人工确认；生产写入需要用户单独批准及可回滚备份。
3. 第二引擎使用离线 fastText `lid.176.ftz`，来自官方发布地址并在运行前检查 SHA-256 `8f3472cfe8738a7b6099e8e999c3cbfae0dcd15696aac7d7738a8039db603e83`。模型为 176 语言通用识别器；`zh` 无法可靠判断简体/繁体，仍须结合文字证据人工核对。
4. fastText 结果达到不少于 40 个文字字符、模型分值不低于 0.85、与次高候选差距不低于 0.25 才视为本次**强候选**；阈值是保守的技术筛查条件，不代表精确的概率校准或人工确认。
5. 所有判断只在 GitHub runner 的内存中运行；日志输出按类别聚合，**不输出患者原文、帖子 ID、账号信息**。不将生产正文复制进开发预览数据库。
6. 安全修正：开发分支的新工作流不读取生产 D1 Token，只允许公开 GET；生产 D1 的验证记录需要后续走受保护的只读审计流程。GET 返回 429 必须停止，不能无视限流继续访问。
