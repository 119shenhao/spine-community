# CDN + R2 实施进度

## 2026-11-08 确认统一按需生成

- 首页「最新帖子」各页、帖子详情和回复分页统一按需生成。上线时无需预生成首页 JSON 或批量回填旧帖。数据库迁移可以保留版本记录，缺少公开副本的记录不触发 R2 写入。
- 匿名访客先请求当前环境的 CDN。文件缺失（HTTP 404）或返回失效占位时，通过原有 Worker 请求读 D1。Worker 验证匿名标准路由、目标及页码，确认 R2 缺失或已失效，随后用同一次请求的后台任务补写这一页。公开内容采用固定对象键，回填同一页合并，正常命中不调用帖子读取 API。请求超时、无效响应、搜索、登录后的私有读取和撤回占位仍按各自路径处理。
- 修改内容时，在 D1 写入事务中推进版本。后台只处理已经发布或已预留的对象，先清除其 R2 正文，再清 CDN。仍可读取的内容使用失效占位，之后首次读取再生成。已隐藏内容使用撤回占位，禁止按需补回。软删除保留原有 Worker 删除占位和仍可见的回复。涉及正文、标题或隐私撤回时按对象路径清理 CDN 的缓存变体。失败记录在队列并退避，生产启用公开读取前需要验证定时处理与撤回时限。
- 正式发布时，应先应用迁移、确认生产队列和回退开关可用，再打开 CDN 公开读取。用开发环境的虚构数据验收初次读取、后续命中、编辑与撤回。此次仅授权开发预览和文档，生产发布仍按项目发布流程单独确认。

## 实现与接口

- [当前开发提交 49e7778](https://github.com/119shenhao/spine-community/commit/49e77784becb262b3252f456042ecf41b6c9dda7)。迁移 `0008`、`0009`、`0010` 新增投影版本、待办、对账快照和持久计数。既有直写生产 SQL 经触发器同事务登记待办，开发分支的新版同步脚本先检查生产投影迁移。现有生产 Actions 固定 SHA 尚未切换。
- 匿名标准最新列表读取 `feeds/latest/page-<n>.json`，每页 20 条；匿名详情及首批 50 条回复读取 `topics/<id>/detail.json`，后续页读取 `topics/<id>/comments/page-<n>.json`。对象统一包含 `schemaVersion`、`contentVersion`、`generatedAt`、`data`，帖子对象另含 `topicId`。R2 自定义元数据保存投影版本与规范化 JSON 的 SHA-256。匿名请求省略凭据，无查询串。发生跨页版本不匹配时，受控回退会重新开始最新列表，或用回复游标查询 D1。
- 登录后含权限/互动状态的读取、搜索和筛选、回复定位、仅查看进展、翻译、统计和既有写操作走现有 Worker 接口。保留根页面的 Preview 防索引处理及统计请求。翻译原文进入公开投影，机器翻译沿用鉴权和可见性检查后的动态接口。
- 同一目标在 D1 内合并待办；普通写入触发同次请求的后台处理，单次最多两步，点赞计数延迟合并。每步读取最新 D1 数据，用 R2 ETag 条件发布，再同时清理无 Origin 和本站 Origin 的规范 URL。只有写入及清理均成功且版本仍相同才推进。失败退避，达到 8 次后进死信。撤回用可版本化的空数据占位覆盖旧对象，以避免过期发布者恢复已撤回内容。
- 站长接口基址 `/api/admin/public-projection`。GET 可带 `scan`、`after` 查看进度、异常和已知 Purge 状态。POST `/start` 接收可选 `target`、`batch_size`（默认 100）、`include_orphans`、`deep`。POST `/step`、`/pause`、`/resume`、`/cancel` 接收 `scan`。POST `/repair` 接收 `scan`、选中的 `keys`（最多 10 个）及 `confirm:true`。POST `/retry` 接收 `key` 和 `confirm:true`。POST `/drain` 只在 Preview 给站长使用，一次最多处理 4 个对象步骤。
- 对账每次最多 5,000 个对象，每批列举最多 100 个、每批比对最多 5 个。R2 分前缀保存游标，列表不足一页继续取 `truncated=true` 的游标。D1 预期键和版本在开始时冻结；同版本时再计算摘要，结尾复核版本。深度对账读取 R2 正文，默认关闭。只报告本功能命名规则内的多余对象；修复重新读取 D1 并提交到待办，涉及撤回时写安全占位。生产 scheduled 处理器只排空待办，没有配置 Cron，也没有自动对账。

## 请求预算与发布前步骤

- 真实业务节省尚未量到。按现有路由计算，无翻译、无额外分页的 1,000 次匿名冷打开，含根页面、`/api/me`、`/api/health`、taxonomy、pageview，正常切流预计从 6,000 次论坛 Worker 请求降为 5,000 次。每次标准站内切页预计从 2 次降为 1 次。回退、登录、翻译和筛选请求须另外计数。
- 每 100 次成功发帖/回帖仍是 100 个相应业务写请求。同次请求的背景处理不增加 HTTP 调用，最多执行 200 个处理步骤。每个步骤最多进行一次 R2 HEAD、一次 PUT、一次 CDN Purge 调用；失败恢复和单独定时调用另计。长列表的稳定分页重建会增加成本并可能积压。未实测远程 D1 行数、CPU、R2 Class A/B 或峰值清理延迟。
- 先在 Preview 配置 Zone ID，经站长手动发布和回填，用虚构测试帖验证缓存 MISS/HIT、清理、正文/回复撤回、失败恢复与计数。核查 CDN 规则对任意查询参数和其他 Origin 的缓存变体，避免出现无法由规范 URL 精确清理的副本。缓存清理故障时，旧公开副本可能保留至 TTL；上线前约定撤回时限和应急停用方案。
- Preview 验收后另行确认生产发布。获批后做生产迁移只读核查及 Time Travel 恢复点，应用并验证 `0008` 至 `0010`，审核新版帖子同步脚本并更新固定 SHA，再发布兼容 Worker。确认生产桶、域名、CORS、Purge、范围和容量，另行批准启用唯一的 outbox Cron、核验按需生成和失效处理后再开启公开读取。故障时先关闭 `PUBLIC_CONTENT_READS` 恢复 Worker 读取，保留待办；需要撤回已有公开对象时另行清理 CDN，不能仅依赖开关。
