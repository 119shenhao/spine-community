## 数据库与自动迁移

- `migrations/preview-only/0001_collector_queue.sql`：`collector_candidates` 储存 `site + source_id`（复合主键）、来源 URL、状态、处理原因、尝试次数、`retry_at`、`updated_at`。不储存患者原始正文。
- `collector_source_state`：为未来各站扫描游标预留 `scan_cursor`、`last_scan_at`。**当前采集程序尚未读写该表，不要把它当成已实现的网页分页断点。**
- 原有 `collect_sources` 仍负责六小时租约、原站 ID 去重、完成状态和帖子关联，`/api/collect/exclusions` 是最终已完成事实来源。
- `.github/workflows/collector-preview-d1.yml`：当 `migrations/preview-only/**` 或迁移配置更新时自动运行 `wrangler d1 migrations apply PREVIEW_DB --remote --config wrangler.collector-preview.json`；也可在 GitHub Actions 手动重新执行。
- GitHub Secrets：`CLOUDFLARE_PREVIEW_D1_API_TOKEN`（仅预览数据库权限为佳），保存在 GitHub Actions Secrets，不能写入仓库或日志。工作流使用 `CLOUDFLARE_ACCOUNT_ID` 和独立预览数据库 ID 核验目标。

## 队列 API（仅预览）

服务入口：`https://feature-v1-community-build-20261106-spine-community.119shenhao.workers.dev`。

`GET /api/collect/queue?site=ask39`：按更新时间返回最多 120 条可处理候选：`pending`；`retry` / `rejected` 且重试时间已到；过期的 `processing`。返回 `{site,items}`；每项为 `source_id,url,status,reason,attempts,retry_at`。同站扫描不足 30 个可处理候选时采集程序才自动重新发现新候选（适用已有自动发现功能的数据源）。

`POST /api/collect/queue`：JSON 请求示例：

```json
{"site":"ask39","action":"enqueue","items":[{"source_id":"12345678","url":"https://ask.39.net/question/12345678.html"}]}
```

`action=mark` 请求示例：

```json
{"site":"ask39","action":"mark","items":[{"source_id":"12345678","status":"retry","reason":"network_error_or_timeout"}]}
```

- 单次最多 30 条，`(site,source_id)` 唯一；相同候选再次入队时 `ON CONFLICT DO NOTHING`，不会重置已有失败/完成状态。
- URL 必须是允许来源站点的 HTTPS URL，主机、路径和源 ID 要匹配；路径不满足规范将拒绝。
- `retry`：平方退避，最大一天；`rejected`：30 天后进入可复查队列；`completed`：只有原有 `collect_sources` 已确认完成，才允许队列更新为已完成。
- 预览采集 API 仍按既有要求免额外密钥，但保留来源校验、速率限制、原站唯一标识和认领租约。**务必不要将该接口发布为生产可用接口。**
- 队列保存元数据，不保存临时认领令牌；令牌仍只在采集任务内存内使用。
- 采集程序脚本：`scripts/spine_collect.py`。先读已完成 exclusions，再优先使用 D1 队列；队列不足则调用对应站点发现逻辑；逐条 claim、抓取原文、验证、complete、论坛读回检查、mark；失败 release 并记录重试或拒绝。

## 已知限制及下一步

- `collector_source_state` 的网页分页游标尚未接入自动发现器；现有断点续采保证的是**已入队候选**和**已完成来源 ID**，不是扫描网页中的页内断点。
- 采集完成数量取决于外站页面可用性、授权、真实内容完整性和质量过滤，不能将任务运行绿灯解读为目标篇数已经达到。必须读取采集 workflow 的 `run_summary`、`collection_summary` 及 `imported` 日志。
- 生产库数据发布不随采集任务自动执行，必须使用独立同步流程。


## 2026-11-08：新增四站公开候选自动发现

代码范围（开发分支 `feature/v1-community-build-20261106`）：
- `scripts/spine_discover.py`：从固定公开列表和公开搜索索引中提取候选 URL，仅收集元数据；强制核对来源主机与来源 ID，且不从候选发现时抓取正文。遇来源返回禁止访问，停止对同一被拒绝主机的后续请求。
- `scripts/spine_sources.py`：补充 Patient.info 新域名 `community.patient.info/t/<slug>/<id>`，保留旧 `patient.info/forums/discuss/<slug>-<id>`；导入仍经 `post_stream` 完整性验证。
- `src/collect.ts`：开发队列接受两种 Patient.info 官方链接形式，拒绝跨域、不匹配 ID 以及跟踪查询参数。
- `scripts/spine_collect.py`：`mode=discover` 仅将候选存入开发 D1，不认领和导入正文；`mode=collect` 优先消费 D1 队列，不足时尝试从这些来源发现候选。原有 `claim → complete`、失败重试及质量过滤维持。
- `.github/workflows/spine-collector-on-demand.yml`：当请求指定寻医问药并进行完整采集时安装 Playwright Chromium；单纯发现不需要浏览器。
- `tests/test_spine_discovery.py` 和 `tests/community.test.mjs`：校验现代 Patient.info URL、候选过滤与 D1 URL 验证、拒绝访问处理。GitHub 代码检查 [#42456509923](https://github.com/119shenhao/spine-community/actions/runs/42456509923) 通过。
