# 开发环境采集队列：D1 持久化与自动验证（2026-11-08）

## 范围与隔离

采集任务、候选状态和队列迁移只允许使用 Cloudflare **开发预览环境** D1：`spine-community-db-preview`（ID `4362537a-5748-4a05-b0c4-219c3db36996`）。
生产环境不运行采集任务，不应用 `migrations/preview-only` 迁移，不开放可用的采集 API（生产请求由现有预览门禁拒绝）。生产帖子只通过独立的开发库到生产库审核/同步流程写入。

代码在分支 `feature/v1-community-build-20261106`，此文件及其他规范文档统一位于 `main/docs`。

## 数据库与自动迁移

- `migrations/preview-only/0001_collector_queue.sql`：`collector_candidates` 储存 `site + source_id`（复合主键）、来源 URL、状态、处理原因、尝试次数、`retry_at`、`updated_at`。不储存患者原始正文。
- `collector_source_state`：为未来各站扫描游标预留 `scan_cursor`、`last_scan_at`。**当前采集程序尚未读写该表，不要把它当成已实现的网页分页断点。**
- 原有 `collect_sources` 仍负责六小时租约、原站 ID 去重、完成状态和帖子关联，`/api/collect/exclusions` 是最终已完成事实来源。
- `.github/workflows/collector-preview-d1.yml`：当 `migrations/preview-only/**` 或迁移配置更新时自动运行 `wrangler d1 migrations apply PREVIEW_DB --remote --config wrangler.collector-preview.json`；也可在 GitHub Actions 手动重新执行。
- GitHub Secrets：`CLOUDFLARE_PREVIEW_D1_API_TOKEN`（仅预览数据库权限为佳），保存在 GitHub Actions Secrets，不能写入仓库或日志。工作流使用 `CLOUDFLARE_ACCOUNT_ID` 和独立预览数据库 ID 核验目标。

## 队列 API（仅预览）

服务入口：`https://feature-v1-community-build-20261106-spine-community.119shenhao.workers.dev`。

`GET /api/collect/queue?site=ask39`：按更新时间返回最多 120 条可处理候选：`pending`；`retry` / `rejected` 且重试时间已到；过期的 `processing`。返回 `{site,items}`；每项为 `source_id,url,status,reason,attempts,retry_at`。同站扫描不足 30 个可处理候选时采集程序才自动重新发现新候选（适用已有自动发现功能的数据源）。

`POST /api/collect/queue`：JSON 请求示例：

```json
{"site":"ask39","action":"enqueue","items":[{"source_id":"12345678","url":"https://ask.39.net/question/12345678.html"}]}
```

`action=mark` 请求示例：

```json
{"site":"ask39","action":"mark","items":[{"source_id":"12345678","status":"retry","reason":"network_error_or_timeout"}]}
```

- 单次最多 30 条，`(site,source_id)` 唯一；相同候选再次入队时 `ON CONFLICT DO NOTHING`，不会重置已有失败/完成状态。
- URL 必须是允许来源站点的 HTTPS URL，主机、路径和源 ID 要匹配；路径不满足规范将拒绝。
- `retry`：平方退避，最大一天；`rejected`：永久退出自动重试队列，避免重新检查已认定不合格的来源（人工复核需显式操作）；`completed`：只有原有 `collect_sources` 已确认完成，才允许队列更新为已完成。
- 预览采集 API 仍按既有要求免额外密钥，但保留来源校验、速率限制、原站唯一标识和认领租约。**务必不要将该接口发布为生产可用接口。**
- 队列保存元数据，不保存临时认领令牌；令牌仍只在采集任务内存内使用。
- 采集程序脚本：`scripts/spine_collect.py`。先读已完成 exclusions，再优先使用 D1 队列；队列不足则调用对应站点发现逻辑；逐条 claim、抓取原文、验证、complete、论坛读回检查、mark；失败 release 并记录重试或拒绝。

## 已知限制及下一步

- `collector_source_state` 的网页分页游标尚未接入自动发现器；现有断点续采保证的是**已入队候选**和**已完成来源 ID**，不是扫描网页中的页内断点。
- 采集完成数量取决于外站页面可用性、授权、真实内容完整性和质量过滤，不能将任务运行绿灯解读为目标篇数已经达到。必须读取采集 workflow 的 `run_summary`、`collection_summary` 及 `imported` 日志。
- 生产库数据发布不随采集任务自动执行，必须使用独立同步流程。

## 2026-11-08：39健康问答采集筛选规则改为三步（用户最新确认）

**适用范围：仅 `ask39` 采集器；不改变其他五个站点的原文/回复完整性或审核策略。** 具体规则如下：

1. **列表初筛**：问题标题与颈椎／腰椎主题相关，且问题标题无广告即可进入候选。不要求标题达到24字，也不要求出现「我／本人／术后／复发」等个人经历词。广告过滤只检查对应患者问题标题，不把网页推荐位或页面侧栏当作用户帖子。
2. **正文校验**：提取患者原始病情描述及患者补充内容，去除空白和常见标点后不少于 **24 个字符**；标题或患者正文存在明确商业推广、诱导添加社交账号、加群、跳转营销链接等广告时拒绝。**已取消个人叙述词强制要求**；医生回答长度不能代替患者正文长度。
3. **回复校验**：至少有 **1 条非广告、可真实读取的有效回复**。无回复、全部是广告，或没有真实回复正文的帖子不导入；遇到明显广告回复则跳过该条，仅保留未改写的非广告回复；不再要求「导入回复数量」与原页面可能包含非回复片段的通用 CSS 选择器数量相等。仍保留重复回复ID、结构未验证、隐藏/展开内容和隐私标识符检查，避免伪造、截断或将广告正文传播到论坛。
4. **广告识别范围**：帖子标题、患者正文、实际回复内容；不把网站自身广告位、页脚、导航或医生正常医疗建议当成用户发布广告。采用明确营销线索规则（引流微信／QQ／公众号、领券优惠、营销链接、加群及下单等），不是百分百准确的 AI 广告鉴定；正式发布前仍需管理员审核。
5. **失败与重试**：仍由开发环境 D1 队列负责状态与去重，采集只写入开发 D1，不同步生产。

### 存储与安全
- 新增预览专用迁移 `migrations/preview-only/0002_collector_mayo_long.sql`：`collector_mayo_stage` 存标题、原文、页数和指纹；`collector_mayo_pages` 存逐页保存标识、内容指纹及数量；`collector_mayo_comments` 只保存解析后的回复正文、独立内部 UUID、原站回复 ID、父回复 ID、页码和次序，**不保存 HTML、Cookie、凭据或原站作者账号**。所有暂存内容仅在独立预览 D1 内，不进入普通帖子列表。
- `collector_mayo_publish_guard` 的 D1 触发器在单一事务中核验：每页都已提交、每页的回复数量合计与暂存行数一致、正式评论行数与暂存行数一致、主帖指纹匹配。若不通过，整笔事务回滚，不会留下“只有部分回复却标记完成”的公开主帖。
- 凭原有6小时独占租约执行暂存操作；重新认领后，`status` 可返回已保存页码并跳过它们。重复提交相同页面可幂等返回；同一页内容变化则拒绝。若结构变化严重，可由持有当前有效租约的采集器显式 `reset` 暂存；**一般网络错误不得自动清空已保存页面**。
- 每个 `/page` 请求最多30条回复，JSON请求仍受150KB上限；每批都独立写D1，正式发布时无原先49条**整帖**回复上限。保留 **400页的资源安全上限**；超出仍拒绝并报告，防止恶意消耗免费D1/Worker资源，后续可在预算和性能验证后调整。
- 回复通过原站 `comment-<ID>` 和 `/comment/<parent>` 关系还原，剔除页面中的引用预览；缺失父节点、顺序不符、重复 ID、隐私风险、正文不完整或未采集的媒体会中止发布而不截断内容。保留对内容完整性与隐私的检查，不会把无法保存的图片内容当作“完整原文”。
- `claim → stage/start → stage/status → stage/page × N → stage/finish → 读回验证 → queue mark completed`；只有 `finish` 真正完成后才能将来源设为 `completed`。若中途失败则 `release` 租约，未完成的暂存页仍保留供后续运行接续。
- 对之前因旧5页/49回复规则被拒绝的 Mayo 候选，支持 **仅 Mayo、仅旧尺寸/结构拒绝原因、仅第一次失败** 的 `queue action=reconsider`；不会自动重处理已完成主帖。

### 预览接口

全部是 `POST` JSON，根地址为开发预览 Worker，必须有该原帖当前有效的 `claim.lease_token`：

```text
/api/collect/long/start   {site:"mayoclinic",source_id,lease_token,expected_pages,title,body,source_lang:"en"}
/api/collect/long/status  {site:"mayoclinic",source_id,lease_token}
/api/collect/long/page    {site:"mayoclinic",source_id,lease_token,page_number,comments:[
   {source_comment_id:"123",parent_source_comment_id:null,body:"...",source_lang:"en"}
 ]}
/api/collect/long/finish  {site:"mayoclinic",source_id,lease_token}
/api/collect/long/reset   {site:"mayoclinic",source_id,lease_token}  # 仅显式修复
```

`finish` 返回 `topic_id`、`imported.topics`、`imported.comments` 和服务端读回的 `persisted_comments`。**请勿把阶段性“保存第N页”日志解释为已成功向论坛发布**。只有成功 `finish` 和后续原站状态核验才算完成。
