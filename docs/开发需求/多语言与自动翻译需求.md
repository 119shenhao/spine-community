# 多语言与自动翻译需求（首版产品规则定稿 · 2026-11-08）

## 2026-11-09 已确认：公开译文先读 CDN

- 公共列表、帖子详情和普通回复分页优先读取同一公开 R2/CDN JSON。JSON 中存在目标语言且匹配原文 `content_version` 的译文时直接显示，并保留切换原文的入口。该翻译路径不请求 Worker。
- 仅当 CDN 缺少当前译文时先显示原文，再按可见范围请求 Worker。D1 已有译文就复用并补回现有公开 JSON，D1 缺失时才调用 Azure。私有数据继续走现有接口。
- 公开译文沿用原文的 R2 更新、CDN 清理及缓存边缘有效期。清理失败时，边缘仍可能短暂保留旧副本。启用直读前必须验证开发 CDN 遵守明确的边缘缓存上限，并验证编辑、隐藏后的撤回。

> 本文件是多语言及自动翻译功能的**唯一详细需求正文**；统一维护于 `main/docs/开发需求/`。同目录的《项目需求总览》和《需求决策记录》只保留摘要与指向本文件的链接。

> 最终决定：2026-11-08。Azure Translator 标准翻译（NMT）为首版唯一供应商；自动语言识别、按需翻译、用尽免费额度直接暂停、沿用现有 D1/R2＋CDN 和 `content_version`；每条译文保存实际翻译来源。首版取消翻译错误上报及后台译文修订。**本次仅更新需求文档，不修改代码、数据库或环境配置。**

## A. 已确认的用户体验

1. **共享全球社区**：八种界面语言共用帖子、回复、账号与后台，不分七个独立论坛。
2. **首访语言**：依据浏览器偏好选择初始界面语言；用户可手动切换并记住选择。用户的主动选择优先。`zh-TW`、`zh-HK`、`zh-MO`、`zh-Hant`（含其地区变体）自动显示 `zh-TW` 界面，`zh-CN`、`zh-SG`、`zh-Hans` 显示简体中文。香港和澳门不另设独立语言版本。
3. **八种界面语言（已扩展）**：英语 `en`、简体中文 `zh-CN`、**繁体中文 `zh-TW`（台湾、香港、澳门共用）**、西班牙语 `es`、巴西葡萄牙语 `pt-BR`、德语 `de`、法语 `fr`、日语 `ja`。这些是初始建议的语言代码，地区细节可调整；未来可增加印尼语、俄语等。
4. **默认发帖语言（2026-11-07 已确认）**：个人中心初始“跟随界面语言”，用户可手动固定并恢复跟随；输入表单按偏好预选语言。**2026-11-08 补充：预选不等于实际语言，发布时系统自动检测，允许用户手动指定或纠正原文语言标签**；编辑既有内容时不自动篡改原文。
5. **发帖／回复原文（已确认）**：用户可用任何语言发布主帖和回复，系统保存用户实际提交的原文及其语言，译文单独缓存且不得覆盖原文。原文隐藏或删除后，按隐私与删除规则处理，不得继续通过译文缓存公开。
6. **自动翻译默认开启**：阅读者直接看到自己所选语言的外语帖内容，原文不需要另行翻译；在同一帖子里，多语言回复也能相互理解。
7. **原文随时可查**：提供“查看原文／查看翻译”切换，标注“机器翻译”，尤其提醒药物名称、剂量和诊断术语可能错误。
8. **实际语言自动检测**：新主帖、普通回复、楼中楼均自动检测实际内容语言，不只依赖界面或默认发帖语言；中外文混用、文本太短等无法可靠判断时保留原文，不强制自动翻译；允许作者纠正原文语言标记。

## B. 已同意的成本节约原则

采用“**自动呈现 + 按需生成 + 持久缓存**”，不是把所有帖子提前批量翻成八种语言。

- 首页／列表：只处理当前展示的标题和摘要，不预翻译全部历史内容。
- 详情页：访问时翻译正文；回复按当前显示的范围／分页处理，不一次翻译所有历史回复。
- 首次实际需要目标语言且无有效缓存时，由后端调用 Azure；译文和真实翻译来源持久保存，共享给相同语言的读者，并复用现有 D1／R2＋CDN 缓存架构。
- 原文编辑后旧版本译文立即视为无效；新译文生成前显示最新原文，不能继续显示与原文不一致的旧译文。
- 同一内容 ID、原文版本、文本部分和目标语言的并发翻译请求应合并，避免 Azure 额度被重复扣减。
- **首版只使用 Azure 免费额度**，服务端按日／月统计并预留安全余量及并发预约，免费额度耗尽或无法确认仍在免费范围内就暂停新翻译，**不自动收费、不自动升级、不开发付费翻译开关**。免费额度恢复后重新按需翻译，不主动批量补翻。
- 翻译失败、额度耗尽或语言无法确定：有效缓存继续展示；没有有效译文则显示原文，绝不隐藏内容、编造译文或调用付费翻译。
- 界面文案翻译可以随代码维护，与需要持续 API 调用的用户内容翻译分开。

### 2026-11-08 — 首屏原文先行、异步自动翻译（已确认）

用户强调翻译质量第一、费用第二；允许新译文在页面展示后逐步生成，**不要求等待翻译完成才能打开页面**。本节补充此前“自动呈现 + 按需生成 + 持久缓存”原则，不推翻原文永久保存与隐私规则。

1. **已确认：首屏不阻塞。** 当目标语言与原文语言相同，或已命中该内容对应的有效目标语言缓存时，立即显示原文或现成译文；**缓存不存在时立即显示原文**，不等待外部翻译 API 才展示页面。
2. **已确认：后台按需翻译。** 用户打开首页列表、帖子详情或当前可见回复时，为需要翻译且无缓存的内容异步请求翻译；翻译结束后**仅局部更新相关文字为论坛当前选定语言，不刷新整页**，并保留“查看原文／查看翻译”按钮。初始未命中缓存时，可在卡片／正文旁显示不打扰阅读的“翻译中”提示（界面具体样式待设计）。
3. **已确认：缓存共享复用。** 译文基于稳定内容 ID、**已有 `content_version`**、目标语言、文本部分识别；直接沿用项目已有的 R2＋CDN 按需回填、投影 `version` 与缓存清理机制，**不新增独立翻译版本号或另造一套基础缓存架构**。公开 JSON、R2/CDN 中的译文纳入既有失效流程；具体投影适配、存储形式及失败保护在开发验收时确定。
4. **建议的交互细节（待开发设计确认）：** 优先翻译用户当前实际看到的标题／摘要和回复，滚动、翻页后按需处理新进入可见范围的内容；防止长列表一次性批量付费。用户主动切换为“查看原文”或在翻译期间变更界面语言时，过期异步结果不得错误覆盖用户当前视图。
5. **已确认：降级阅读。** 翻译慢、失败、服务超额或费用保护触发时继续展示原文，绝不显示空白或捏造译文；可提示未翻译及稍后重试，重试与并发需限流。
6. **已确认的优先级：翻译质量 > 翻译费用 > 首次翻译速度。** 患者口语、医学术语、病程叙述、否定词、药品名称、数值和剂量不得擅自推断或增删事实；机器译文不是医生审校，仍允许随时核对原文。
7. **已定供应商：** 首版直接采用 Microsoft Azure Translator 标准文本翻译（NMT），**不再安排其他厂商对比测试**。正式接入前仍核对 Azure 的免费额度、服务条款、语言支持、健康内容隐私及费用控制，不代表已经开通账户或授权收费。

**状态：2026-11-08 已记录产品体验与优先级；仅需求文档更新，未修改代码、数据库、翻译 API 配置或生产部署。**

### 2026-11-08 — 翻译实现技术路线（已确认）

**首版采用后端翻译服务，不采用前端 JavaScript 翻译作为主方案。** 翻译供应商已最终选定 Azure Translator 标准文本翻译（NMT）；尚未批准修改代码、数据库或购买服务。

- **后端职责：** 由可信的服务器端（如 Cloudflare Worker）在有真实用户访问、目标语言不同且无有效缓存时，按需调用经评估的第三方翻译 API；翻译结果按内容 ID、版本、目标语言及标题／摘要／正文／回帖等部分独立持久缓存，同语言用户共享，避免重复计费。
- **前端职责：** JavaScript 仅负责界面语言、原文／译文切换、翻译进度提示、翻译完成后的局部更新和失败回退；**不在浏览器端直接调用需保密的翻译 API 密钥，不集成第三方网页翻译插件，也不下载本地翻译模型。**
- **不改变既定用户体验：** 缓存未命中先显示原文，后台翻译完成自动替换，无须整页刷新；只处理实际访问的帖子、当前可见的回复及楼中楼，保留“查看原文”。
- **缓存架构协同：** 译文纳入项目现有 D1／R2＋CDN 公开 JSON 按需回填体系，复用原有内容版本及缓存失效，不预先批量生成所有语言版本；译文接入这套机制仍须适配和测试，不能把既有原文缓存功能误认为已经自动支持译文缓存。
- **暂缓方案：** 浏览器自带网页翻译、前端加载在线翻译插件、浏览器内置 Translator API 及前端加载翻译模型，**首版均不实施**，未来有可靠的兼容性、商业授权、医学翻译质量证据时可重新评估。
- **供应商已定：** 首版固定使用 Azure Translator 标准文本翻译（NMT），不执行跨供应商翻译对照测试；仍应做 Azure 自身医学术语准确性、商用条款、健康信息隐私、语言覆盖及费用控制验收。

### 2026-11-08 — 翻译技术路线选定：后端按需翻译（已确认）

1. **确定后端服务端翻译为主方案**：由 Cloudflare Worker 在需要且无有效译文缓存时调用第三方翻译 API；主帖、标题／摘要、普通回帖和楼中楼按实际访问范围分开翻译、分开缓存。不在发帖时预翻译所有语言。
2. **前端只负责显示及交互**：用户进入页面时，目标语言译文已缓存则立即显示；未命中时先展示原文，后端异步生成并持久保存译文，完成后前端局部替换文字、不刷新整页，并提供“查看原文／查看翻译”切换。
3. **不采用前端 JS 翻译作为当前实现**：暂不接入 Google/第三方网页翻译脚本、浏览器内置 Translator API 或浏览器下载运行的本地翻译模型。此类方案仅保留为未来可能的独立备选，**不得作为首版依赖，也无需为它们开发功能**。
4. **质量优先、成本可控**：已确定 Azure Translator 为唯一首版供应商，无需比较或接入 Google、阿里云、OpenAI 等其他厂商。开发时仍须验证 Azure 医学内容准确性、语言覆盖、隐私、失败降级与费用上限；**供应商选型已定，不等于已批准外部 API 接入或付费操作**。
5. **直接复用既有版本与缓存**：主帖／回复现有 `content_version`，公开 JSON 投影有自己的 `version`；译文关联前者，由已实现的 R2＋CDN 按需回填与失效机制负责分发及清理，不额外新增一套翻译版本管理。编辑、删除、权限变化后禁止继续公开旧译文；数据投影集成需开发和测试。

**执行边界**：本次是需求和技术方向定稿，暂不修改代码、数据库、Cloudflare 配置或线上部署。

### 2026-11-08 — 确定 Azure 为首版翻译服务商、逐条记录译文来源（已确认）

**供应商选择已定：首版只使用 Microsoft Azure Translator 的标准文本翻译服务（神经网络机器翻译 NMT），由后端调用。不再进行 Azure、OpenAI、阿里云等服务商的 A/B 对照测试，也不开发多服务商自动分流。** 将来如确需更换供应商，可依据每条译文的真实来源进行迁移和重译；Azure 的当前额度、商用条件、语言覆盖、数据处理条款和 API 配置，在正式接入前仍须核验。此决定**并不代表已配置 Azure 账户、密钥、实现接口、建表或上线**。

**每一条已持久化的机器译文必须有可追溯的翻译引擎来源，不能只在全站配置中保存“当前默认 Azure”。** 主帖标题／摘要／正文、普通回复、楼中楼等各自生成的译文记录都要关联其实际使用的供应商与产品；不同语言、不同源内容版本可能由不同引擎生成，不能仅按帖子记录一次。

建议译文持久化元数据（字段名与表结构留待设计审核）：

- `provider_id`：服务商稳定标识，例如 `azure`、`openai`。
- `product_id` / `engine_type`：实际产品及翻译技术，例如 `azure_ai_translator_text` / `nmt`；不得只记录笼统“AI 翻译”。
- `model_id`、`model_version`：若供应商 API 能明确返回或配置则保存；Azure 标准翻译若未提供具体内部模型版本，记录为未知／空值，**不得编造**。若使用自定义翻译器，也应记录对应部署／配置标识。
- `source_content_type`、`source_content_id`、`source_part`、`source_version_or_hash`：对应的主帖／回复／楼中楼及标题、摘要、正文等内容部分和原文版本／哈希。
- `source_language`、`target_language`、`translated_at`：原文语言、目标语言、成功生成时间。必要时记录翻译策略／术语表或提示词版本，以便质量回溯。

**写入与更新规则：**
1. 首次成功翻译并保存译文时，译文文本与上述来源元数据必须在同一逻辑写入中落库；翻译失败、取消或只读原文时不能伪造译文来源。
2. 命中缓存时保留**生成这条译文当时**的供应商／模型信息；日后将默认供应商由 Azure 换成 OpenAI，不得把旧 Azure 译文误标为 OpenAI。
3. 原文被编辑、删除或权限变更时，按既有缓存失效规则处理；重新翻译应建立新版本的有效译文记录并记录新引擎来源，不能沿用旧来源元数据。
4. 后续支持站长按服务商、产品、语言和原文版本筛选缓存，识别需要重新翻译的内容，以便逐步替换、质量复核，不必批量清空所有译文。
5. 若存在历史未记录来源的译文，只能标记为 `unknown`／待核查，不得推测填成 Azure。
6. 如译文另行发布到 R2/CDN，仍应以数据库中的元数据为可追溯依据，静态缓存的元信息不得与其冲突。
7. 前端继续标明“机器翻译”、保留“查看原文”；可显示明确的实际服务商产品名称（例如“由 Microsoft Azure Translator 翻译”），名称必须取自该条译文的真实来源，不能从全局当前默认配置推断。

**范围：** 只确认需求与数据追溯设计。正式开发时需要 D1 迁移方案和测试，现阶段不修改代码、数据库、Cloudflare 配置或生产站点。

### 2026-11-08 — 最终确认：自动检测、限额暂停、复用既有缓存（首版）

1. **语言**：系统自动识别每条主帖和回复实际语言，不能因用户选了英文界面便默认英文原文；作者可以手动指定／纠正。短句、混合语言等无法可靠识别时，不强行翻译，继续显示原文。
2. **免费额度**：首版只在 Azure 的免费额度内翻译。达到服务端设置的保守限额、调用方返回额度不足，或无法确认仍处于免费范围时，立即停止新的翻译调用。已有有效缓存可继续显示；无缓存则展示原文；确认免费额度恢复以后再按需生成。**不支持自动充值、升级或管理员手动开付费翻译**；限额必须考虑并发、失败、预留安全余量，不能把提醒当作硬性保护。
3. **原文与缓存**：使用代码中已经存在的帖子／回复 `content_version`，译文按其关联版本管理，**不创建另一个翻译版本号**；继续沿用 D1、R2＋CDN 公开 JSON 按需回填和失效框架。原文一经编辑，旧译文不可显示；用户先看最新原文，实际有人阅读时再翻译新版本。具体存储形式、翻译结果如何进入现有公开 JSON、CDN 失效失败时的防旧版本保护，均为开发适配及测试事项，不等于已经实现。
4. **去重**：以内容、现有内容版本、文本部分和目标语言区分翻译任务；相同请求并发合并，同语言用户共享已缓存结果。不因发帖、点赞或部署批量预翻译内容。
5. **隐私**：只把公开且允许读取的文字发送 Azure，隐私政策和发帖提示明确告知第三方机器翻译；不发送私密草稿或无关身份数据。

### 2026-11-08 — 首版不做的功能（用户明确取消）

- **不做“报告翻译错误”按钮、用户译文上报、后台翻译错误管理列表、管理员手动编辑译文以及后台手动重翻功能**。此前讨论过的工作流已撤回，不能再当成首版需求。
- 不开发前端 JS 网页翻译、第二家翻译服务商、跨供应商质量对照测试，也不开放付费翻译功能。原有一般内容举报机制不受影响，不等同于翻译错误举报。

## C. 服务选择（**Azure 已最终选定；具体接入尚未实施**）

- **已最终选定：Microsoft Azure Translator 标准文本翻译（NMT）**。后端按需翻译、数据库逐条存储每条译文的真实翻译来源与产品。首版不做供应商对比测试，也不集成第二家翻译服务商。
- 尚未批准创建第三方付费账户／密钥、升级计费套餐或自动充值；**不能把价格或免费额度视为永久保证**，接入前必须重新核对供应商规则和可用地区。
- 需要确认：第三方隐私条款、医疗相关敏感内容能否传输、合规地区、数据保留、访问限制、真实硬性用量控制。

## D. 安全、隐私和健康内容（首版已确认）

- **只翻译有权公开浏览的内容**：公开正文按权限校验后才可以发送至 Azure；私密草稿、未审核／已隐藏／已删除内容不得被提交给第三方。后端必须再次核验，不能只靠前端限制。
- **用户隐私告知**：在发帖提示和网站隐私政策中说明公开患者经历可能发送给 Microsoft Azure Translator 进行机器翻译，告知用途、第三方及相关数据处理方式，正式上线前核对供应商的隐私条款、跨境传输与适用法律。不额外传输邮箱、登录凭证等无关身份资料。
- 用户原文语言与阅读语言相同时不调用翻译；自动检测不能可靠判断时保留原文，允许作者纠正语言标签。
- 自动译文不是医学审校：左右侧、否定词、药名、剂量和诊断术语可能出错，始终保留查看原文入口。

## E. SEO 与查找（方案待讨论）

- 规划语言路径，例如 `/en/`、`/zh-cn/`、`/es/`、`/pt-br/` 等；实现方式、slug、canonical 与 hreflang 仍待讨论。
- 不应自动将所有未经人工质量检查的机器翻译页面都开放搜索引擎收录；优先考虑少量高质量公开索引页面。
- **已确认（2026-11-06）**：默认检索全球所有语言的公开帖子，读者所选界面语言决定默认译文展示而非限定原帖语言；默认“最相关”，可切换“最新”“讨论最多”。跨语言症状概念、原文全文搜索与关键词扩展应共同参与，不能依赖按需生成的译文缓存已经存在。详情参见 [症状搜索需求](跨语言症状搜索需求.md)。

## F. 数据结构预留与验收（**仅需求确认，不授权本次建表**）

- 用户语言偏好、自动识别的原文语言、作者人工指定／纠正语言标记及无法可靠识别时的回退状态；
- 帖子／回复原文、原文语言、正文版本；
- 每条译文对应的内容 ID／部分、原文语言与版本／哈希、目标语言、实际翻译服务商（provider）、产品／引擎（product/engine）、可取得的模型信息及生成时间；换引擎后不得篡改旧译文来源；
- Azure 按日／按月用量、并发预约与费用熔断状态、免费额度恢复状态；
- 公开／私密权限检查与被删内容缓存清理。

**验收要点**：语言识别准确与不确定时的回退、Azure 额度耗尽直接暂停、有效缓存复用、并发翻译去重、原文修改／删除时旧译文不可见、CDN/R2 清理与按需回填、翻译来源可追溯、隐私告知和第三方权限限制。具体 D1 字段及 R2 JSON 集成方式在开发时设计测试，本次不运行迁移。
