# Spine Community：Google 帖子发现与 SEO 技术改造

> 确认日期：2026-11-10；用户要求先解决 Google 能否正确发现、抓取每一篇公开帖子的问题，再开始外部推广。
> **程序开发分支**：`feature/v1-community-build-20261106`。**文档只存 `main/docs/`**。未经用户另行明确批准，不将程序发布到生产，不操作生产 D1。

## 一、问题与目标

原站采用 `/#/topic/<id>` 的片段路由，页面正文由前端 JavaScript 异步获取；这种地址不能可靠地作为 Google 的独立可抓取帖子页面。每篇**已公开**帖子需要有真实 URL、服务端返回可读的原文 HTML、唯一 canonical、标题与摘要，自动进入 Sitemap。对已删除、待审核、隐藏或不存在的帖子，不能暴露私密内容或继续列入 Sitemap。

Google 官方参考：
- [JavaScript SEO 与 History API](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)
- [构建与提交 Sitemap](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)
- [论坛 DiscussionForumPosting 结构化数据](https://developers.google.com/search/docs/appearance/structured-data/discussion-forum)

## 二、已实现的技术设计（以开发分支代码为准）

1. **可抓取路径**：帖子固定为 `https://spine.nbn369.com/topic/<id>`，首页为 `/`。前端通过 `history.pushState` / `popstate` 路由；旧 `/#/topic/<id>` 在浏览器启动时用 `replaceState` 转为正常路径。帖子标题、导航均使用标准 `<a href="/topic/...">` 链接。保留 Google 登录、回复、翻译和评论定位等现有功能。
2. **Worker 服务端 HTML**：`src/seo.ts` 拦截首页与帖子详情，直接从 D1 查询帖子状态、原文标题和正文，安全转义后放入响应的 `<main>`。搜索引擎在不执行 JS 时也能读到原文。浏览器仍加载原有 SPA 代码，支持后续交互和按用户语言展示译文。
3. **元数据**：帖子独立 `<title>`、`meta description`、`rel=canonical`、Open Graph，`<html lang>` 采用帖子原始语言。全部指向生产域名 `https://spine.nbn369.com`，避免 `workers.dev` 别名产生重复收录。未有独立译文 URL 时，不伪造 `hreflang`。
4. **自动 Sitemap**：生产环境的 `/robots.txt` 指向 `/sitemap.xml`。Sitemap 实时从 D1 查询 `status='published'`，无需人工更新；≤500 篇时直接返回 URL 列表，>500 篇时返回索引并分片为 `/sitemaps/topics-1.xml` 等，每片最多 500 个帖子 URL；首页 URL 保留在第一页。标注真实 `lastmod`，不包含未公开帖子；测试覆盖 505 篇帖子无遗漏。Google 对每个 sitemap 的上限是 50,000 URL/50 MB，当前 500 分片保守。
5. **状态与隐私**：不存在、隐藏或待审核帖子返回 HTTP 404 与 `noindex`，不得在 HTML 中泄露原文；删除后的帖子保留供用户浏览的删除占位与回复，但返回 `noindex` 并从 Sitemap 排除。预览站 `robots.txt` 全站禁止抓取、页面 `X-Robots-Tag: noindex`，预览 Sitemap 返回 404。
6. **结构化数据**：对真实社区用户发布的帖子输出 `DiscussionForumPosting` JSON-LD（真实标题、全文、作者昵称、发表时间、评论数）；系统导入的 `Anonymous` 转载帖子不冒充原创作者，不输出这种结构化数据。
7. **安全与费用**：继续使用现有 CSP、X-Frame-Options 等安全响应头。HTML 默认 `no-store`，对帖子实时检查发布状态，避免删除或隐藏后被旧 CDN HTML 缓存暴露。帖子直达页面会增加一次 Worker 和 D1 读取；首页 HTML 不查询 D1；Sitemap 读取公开帖子表。需要在上线后监控 Cloudflare Workers / D1 免费额度。
8. **不更改现有业务数据**：不新增 D1 迁移文件、不复制开发数据到生产、不修改翻译缓存或 R2 CDN 规则。所有已发布帖子的 URL 根据现有 ID 自动生成。

## 三、自动与在线验证

- `tests/community.test.mjs`：原文 HTML、特殊字符转义、canonical、HEAD、公开/非公开 HTTP 状态、隐私无泄露、Sitemap 分页覆盖、旧路由兼容、真实/系统作者结构化数据、CSP、安全头、首页零 D1 查询。
- `npm run verify`：TypeScript 检查 + Node 集成测试，随开发分支 push 自动运行。
- `.github/workflows/preview-seo-smoke.yml`：只读在线冒烟测试，从 GitHub Actions 访问 Cloudflare 预览 Worker；检查首页和帖子 HTML、canonical、预览 `noindex`、预览 robots/Sitemap、未知帖子 404。不读取或输出真实患者正文、不写入 D1。
- **注意**：GitHub 代码检查成功、Cloudflare Preview 构建成功不等于 Google 已收录；生产部署后仍需实测 `/robots.txt`、`/sitemap.xml` 和至少一篇生产帖子页面的 HTTP 源码。

## 四、生产发布后的 Search Console 验收（待用户明确批准发布）

1. 访问 `https://spine.nbn369.com/robots.txt`：确认有 `Sitemap: https://spine.nbn369.com/sitemap.xml`，不是 `Disallow: /`。
2. 访问 `https://spine.nbn369.com/sitemap.xml`：确认 XML 200、包含已发布帖子；当超过 500 篇时逐页检查 `/sitemaps/topics-N.xml`。不应出现未审核或删除帖子。
3. 选一篇公开帖子，直接访问 `https://spine.nbn369.com/topic/<真实ID>`：HTTP 200，**查看网页源代码**（不是只看渲染后 DOM）应有原文 `<h1>`、正文、canonical 和描述。访问不存在的 ID 返回 404，删除/待审核内容不应被索引。
4. 使用 [Google Search Console](https://search.google.com/search-console) 验证 `spine.nbn369.com` 所有权，提交 `https://spine.nbn369.com/sitemap.xml`，用 URL 检查工具抽查一篇真实帖子；检查抓取、索引、canonical 与呈现结果。
5. Google 收录通常需要等待搜索引擎实际抓取；Sitemap 是发现线索，不保证全部或立即收录。后续观察 Search Console 的“网页索引”和“搜索效果”报告，区分“已发现”“已抓取”“已编入索引”。

## 五、后续独立阶段

- 多语言译文若要被不同语言搜索分别收录，必须设计独立、稳定、公开的译文 URL、语言 canonical 与 `hreflang`，不能直接把当前用户选择的语言作为唯一 canonical 内容。
- 根据 Search Console 实际数据再考虑主题分类页 SEO、相关推荐内链、更多结构化数据和性能优化；不要为了 SEO 大量自动制造低质量或虚构患者故事。
